# project-map / 平台产品 → 仓库 映射

> 喂食时据 PM 卡的「产品/模块 + 客户 + 标题关键词」查此表，决定改动落在哪个仓库。
> 平台是组织维度，仓库名是代码仓维度，无约定可推导，必须显式映射。**由负责人维护确认，AI 不猜。**
> 本文件由 `yarn setup` 从 `example/project-map.md` 生成，按你团队的实际产品/仓库填写，不入库。

## 映射表(按行从上到下匹配)

| 平台产品/模块 | 判断规则(标题关键词) | 命中 → 仓库目录    | jenkins job   |
| ------------- | -------------------- | ------------------ | ------------- |
| 示例产品 A    | 含「移动端」         | → `example-repo-mobile` |           |
|               | 其他                 | → `example-repo`   | `example-job` |
| 示例产品 B    | (无条件)             | → `example-repo-b` |               |

jenkins 地址前缀在 `febot.config.json` 的 `jenkins.base`，仓库到 job 名的对应在 `jenkins.jobs`。
本表的 jenkins 列仅作备注，**部署链接以 `febot.config.json` 为准**。

## 判断流程(喂食 skill 执行)

1. 读 PM 卡「产品/模块」，在表的上半部找到对应行。
2. 若该行有「判断规则」，**按关键词匹配需求标题**，命中哪个仓库就用哪个。
3. 命中失败 / 命中多条 / 一产品仍不确定 → **询问负责人**，确认后回填，不许猜。
4. 一产品多仓(前后端分离)时，此表多行，由负责人指明本次改哪个。

## 约定

- 新增 PM 卡时先查此表；查不到 → 在 feed 时向负责人要，确认后回填，不许猜。
- 仓库目录以 `febot.config.json` 的 `repoRoot` 为基准，改动**直接落在该仓的基准分支工作区**里(不建 worktree、不切分支)。
- **基准分支**：从 `febot.config.json` 的 `branches.default` 读取(默认 `dev`)；候选分支见 `branches.candidates`。主仓 checkout 常驻该分支。
- 改动以**未提交**形式留在工作区(不 add/commit)，由 ⑤ 步人工提交；开工前该工作区必须是干净的。
